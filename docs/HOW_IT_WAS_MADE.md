# How *Reel It In* Was Made

This document covers the technical architecture, visual pipeline, and development workflow used to build **Reel It In** from scratch.

---

## 1. Rojo-First, Disk-Only Source of Truth

All game code lives as `--!strict` `.luau` files under `src/` and is synced into Roblox Studio exclusively through **Rojo** (`default.project.json`).
- **No Studio-authored scripts**: Every service, controller, UI component, and config module is version-controlled on disk.
- **Bootstrap + ModuleScript pattern**: `init.server.luau` and `init.client.luau` only bootstrap modules in order (`Init()` to register handlers/state, then `Start()` to begin loops and connections).
- **Zero magic numbers in logic**: All tunables (drop weights, rod stats, weather durations, pond slot costs, quest goals) live in `src/shared/Config/` and are shared between the live game and offline simulators.

---

## 2. Server-Authoritative Gameplay & Economy

All RNG, currency, and inventory mutations happen on the server (`src/server/Services/`):
- **Fishing Loop (`FishingService`)**: Rarity, species, weight ratio, and mutation are rolled server-side at cast time. The reeling minigame runs on the client for instant 60fps responsiveness, and the server validates the reported result against minimum plausible reel time (`Rarities.MinReelTime`) and session state.
- **Single Remote Registry (`src/shared/Net.luau`)**: Every `RemoteEvent` and `RemoteFunction` is declared and created in one place. Client requests are rate-limited, type-checked, and wrapped in `{ ok, error?, ... }` responses.
- **Event Bus (`GameEvents.luau`)**: Gameplay services emit events (`Cast`, `Catch`, `Sell`, `PondPlace`, etc.) rather than calling `QuestService` or `BestCatchService` directly, keeping systems decoupled.
- **Persistence (`DataService`)**: Uses `UpdateAsync` session locking, retries, autosaves, and `BindToClose`. Studio playtests default to in-memory profiles unless `Workspace` has `StudioSavesEnabled = true`.

---

## 3. Client-Side Cosmetic Simulation

The server never simulates cosmetic parts or animations:
- **Swimming Pond Fish (`PondVisualController`)**: Creatures swim locally inside each pond's `Water` volume along smooth cubic Bezier splines, with joints animated in `PreSimulation` via `Motor6D.Transform`.
- **Rods, Lines & Held Fish (`FishingVisualController`, `HoldVisualController`)**: Driven purely by replicated Player attributes (`RodId`, `FishingState`, `HeldSpecies`, `HeldWeight`, `HeldMutation`).
- **Environment & Weather (`WeatherVisualController`, `WaterfallVisualController`, `AmbientController`)**: Lighting, Atmosphere, Clouds, camera-following rain streaks, lightning bolts, waterfall spray/ripples, and bobbing/orbiting map decor all run locally on the client.

---

## 4. Procedural VoxelMorph Rigs & World Builders

Instead of hand-placing thousands of parts in Studio, the world and 3D assets are generated by reproducible Luau builder scripts in `tools/studio/`:
- `BuildGreybox.luau`: Constructs the cliff-ringed basin map, 6 sunken ponds, The Falls & river, the Abyss, boardwalks, fishing zones, and travel markers.
- `BuildEnvironment.luau`: Dresses the basin with trees, rocks, lanterns, NPCs, market stalls, buoys, and animated wildlife within strict part/light budgets.
- `BuildCreatures.luau` & `BuildAbyssalAngler.luau`: Build all 12 VoxelMorph creature rigs with `Motor6D` bone chains (`RootPart > Body > Head > Tail > Fins`).
- `BuildGear.luau`: Builds the 6 fishing rods, 5 baits, and bobber.

Each builder has a corresponding **headless Lune dryrun** (`tools/studio/dryrun*.luau`) that validates part budgets, walkable ground reachability, rig joint pivots, and config contracts before anything is run in Studio.

---

## 5. Code-Authored UI/UX Design System

All UI is built in code under `src/client/UI/` and `src/client/Controllers/` (zero Studio-authored `ScreenGui`s):
- **Shared Kit (`Kit.luau`)**: Nautical carved-wood, warm-brass, and riveted-steel theme (`FredokaOne` display headers, `BuilderSansBold` / `BuilderSansMedium` body copy), quantized `UIScale` (`Kit.AutoScale`) for crisp text across resolutions, and `Kit.IsCompact()` layouts for phones.
- **Procedural Iconography (`DockArt.luau`)**: Multi-layered procedural illustrations for the bottom Navigation Tray (`Backpack`, `Rods`, `Baits`, `My Pond`, `Shop`).
- **3D Item Previews (`ModelPreview.luau`, `PlacePreview.luau`)**: ViewportFrames reuse the exact same `CreatureModel` and world landmark geometry so items look identical in the pond, in hand, and in menus.

---

## 6. Offline Balance Simulation

Before tuning any economy or drop-rate numbers in Studio, `tools/sim/economy.luau` runs the **actual** `src/shared/Config/` modules in **Lune** across hundreds of thousands of simulated casts and 10-hour player progression runs, verifying rarity odds, Colossal rates, mutation probabilities, pond aura math, and slot unlock pacing.
